Give Replit this prompt:

Add a complete forgot password and reset password flow. Do not touch any other features.

Step 1 — Forgot Password page

Create a new page at /forgot-password with a simple centered form:

	•	Showgate logo at the top with a back to home link
	•	Heading: “Reset your password”
	•	Subtext: “Enter your account email and we will send you a reset link.”
	•	Email input field
	•	Submit button: “Send Reset Link”
	•	Link at the bottom: “Remember your password? Log in” linking to /login

Step 2 — Backend forgot password endpoint

Create POST /api/auth/forgot-password that does the following:

	1.	Check if the email exists in the users table. If it does not exist, still return a success message — never confirm whether an email is registered or not for security reasons. Always say “If that email is registered, a reset link has been sent.”
	2.	If the email exists, generate a secure random token using crypto.randomBytes(32).toString(‘hex’)
	3.	Save the token and an expiry timestamp (1 hour from now) to the users table — add columns reset_token and reset_token_expires if they do not exist using ALTER TABLE
	4.	Send an email to the user with the reset link formatted as: https://[your domain]/reset-password?token=[token]
	5.	For sending email use Nodemailer with a Gmail SMTP or use the Resend API if already configured — check what email service is already in the codebase and use that. Add the necessary credentials as Replit Secrets.

Step 3 — Reset Password page

Create a new page at /reset-password that:

	1.	On load, reads the token from the URL query parameter
	2.	If no token is present, redirect to /forgot-password
	3.	Shows a form with:
	•	Heading: “Create new password”
	•	New password input
	•	Confirm password input
	•	Submit button: “Update Password”
	4.	Validates that both passwords match and password is at least 8 characters before submitting

Step 4 — Backend reset password endpoint

Create POST /api/auth/reset-password that:

	1.	Accepts token and newPassword in the request body
	2.	Looks up the token in the users table
	3.	Checks that the token exists and reset_token_expires is still in the future — if expired, return error “Reset link has expired. Please request a new one.”
	4.	Hashes the new password with bcrypt
	5.	Updates the user’s password_hash with the new hash
	6.	Clears the reset_token and reset_token_expires fields so the link cannot be reused
	7.	Returns success and redirects the user to /login with a message saying “Password updated. Please log in with your new password.”

Step 5 — Add link on login page

On the /login page, add a “Forgot password?” link below the password input field that links to /forgot-password.
