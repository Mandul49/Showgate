## Problem
The build fails at the Railpack auto-detected install step (`npm ci`) with:
```
npm error network request to http://package-firewall.replit.local/npm/typedarray/-/typedarray-0.0.6.tgz failed, reason: getaddrinfo ENOTFOUND package-firewall.replit.local
```
The builder is RAILPACK, which auto-detects `npm ci` as the install command. This runs before the user-configured `buildCommand` from `railway.json` (`npm install --legacy-peer-deps && npm run build:server`). The failure occurs at stage-0 step 11/15.

## Diagnosis
The `package-lock.json` was generated inside Replit's environment, which routes npm traffic through an internal proxy (`package-firewall.replit.local`). When `npm ci` runs on Railway, it strictly follows the resolved URLs in the lockfile and cannot reach Replit's internal proxy. The lockfile on `main` HEAD is identical to the failed commit — the Replit proxy URLs have not been cleaned up, so this failure can recur whenever the npm build cache is cold. A previous deployment (928e986a) failed with the exact same root cause.

## Fix
1. **File: `package-lock.json`** — Delete this file from the repository root entirely.
2. Outside of Replit (locally or in a clean environment), run `npm install` (or `npm install --legacy-peer-deps` if needed to match the build command) to generate a fresh `package-lock.json` where all `resolved` fields point to `https://registry.npmjs.org/` instead of `http://package-firewall.replit.local/npm/`.
3. Commit and push the new `package-lock.json` to the `main` branch.

Alternatively, as a text-only workaround, find and replace all occurrences of `http://package-firewall.replit.local/npm/` with `https://registry.npmjs.org/` in the existing `package-lock.json`, though a full regeneration is more reliable and ensures integrity hashes remain valid.
